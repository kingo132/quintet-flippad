# 天地创造 / 创世封魔录 · Pixel 9 / FlipPad

两个独立 Android 应用，共享 Snes9x 执行核心，各自使用专用的完整地图显示器。手机桌面只显示游戏名。版本 0.1.8，Android 17 / API 37，arm64，支持 16 KB 内存页。

此仓库包含完整修改源码、构建脚本、图标及依赖许可。**不包含游戏 ROM、汉化文本、游戏美术、用户存档、签名密钥或含游戏内容的安装包。** 使用自己已有的游戏文件在本地构建。

## 画面与控制

- 默认竖屏、4 倍整数像素，Pixel 9 满宽 270 个真实世界像素；扩展区域读取游戏 WRAM 中的完整地图，不把 VRAM 环形缓冲重复铺到屏外。
- 游戏场景保留原始画面的像素、对话和动画。仅在识别到对应 HUD 时将其移到物理屏幕顶部；不避开摄像头。
- 房间边界以外保留黑色，加载和不支持的场景退回原始画面。原始视野可以在助手中切换。
- FlipPad 弧形底边；插拔手柄自动切换触屏按键。自动视野按屏幕可用高度计算。
- Select 短按：中文游戏助手；长按：原版 Select。Start 保留原版功能。
- L1 / L2：减速 / 加速；R1：缩放视野；R2：滤镜。
- 默认游戏 1 倍速，音乐正常速率（手机媒体静音状态会在助手中提示）；可选 0.5 / 1 / 2 / 3 / 4 倍速。
- 六个独立手动槽，独立后台续玩。写入采用同步临时文件和原子替换，上一份保留 `.bak`。

《天地创造》开场尚未获得箱子时，原版物品菜单不可用，沿用游戏本来的剧情限制。

## 构建

需要 JDK 17、Android SDK 37.0、Build Tools 37.0.0、NDK 28.2.13676358。默认 SDK 路径为 macOS 的 `~/Library/Android/sdk`，其他平台设置 `ANDROID_SDK_ROOT`。支持 macOS / Linux。

```sh
./tools/build_quintet_android.sh
./android-app/gradlew -p android-app assembleRelease \
  -PsoulblazerRom='/absolute/path/SoulBlazer_CN_v0.9.sfc' \
  -PterranigmaRom='/absolute/path/天地创造.sfc'
```

安装包位于 `android-app/app/build/outputs/apk/{soulblazer,terranigma}/release/`。本地发布默认使用 Android 开发签名；更新既有安装应使用同一密钥。发布构建关闭调试入口。

省略 ROM 参数可编译不含游戏的版本，供 CI 检查使用。这种版本不能启动游戏。源文件的 SHA256 在对应 flavor 的资源中固定，运行前会校验输入，避免读错游戏或汉化版本。

## 验证边界

验证包括从空存档启动、中文输入/对话、房间切换、试炼战斗、天地创造村庄及四方向滚动、六槽读写与后台恢复、五档速度、声音输出、触屏布局、图标及 Android 打包。完整原始状态与原始视野的对照检查可使用 `tools/headless.c` 和 `tools/verify_pair.c`，私有游戏和测试进度必须由本地提供。

这是游戏专用的实时扩展显示，尚未完成整部游戏的通关验证。复杂战斗、特殊地图或过场可能回退原始视野；后续发现问题应保留存档和场景记录再修复。

## 来源与许可

基于 [libretro/snes9x](https://github.com/libretro/snes9x) `fae2fea08f74180759ef540ee94259213f503480`。通用 Tall 显示器与 Android 宿主沿用本地 SFC Tall 项目，专用地图显示代码沿用本地 Babel Recomp FlipPad 适配。WRAM 格式独立参照 RustyBlazer / Crysta 交叉核对。

原始 Snes9x 说明保存在 [README-Snes9x.md](README-Snes9x.md)，许可见 [LICENSE](LICENSE)；滤镜及参考项目的具体来源、原始许可和通知见 [android/THIRD_PARTY_NOTICES.md](android/THIRD_PARTY_NOTICES.md) 与 `android-app/app/src/main/assets/notices/`。各组件保留其原有许可，此说明不对依赖重新授权。

私有游戏的自动对照可在本地运行（结果目录不得提交到仓库）：

```sh
make -C libretro platform=osx ARCH=arm64 -j8
clang -O2 -Ilibretro tools/verify_pair.c libretro/snes9x_libretro.dylib -o /tmp/quintet-verify-pair
DYLD_LIBRARY_PATH="$PWD/libretro" python3 tools/verify_quintet.py \
  --binary /tmp/quintet-verify-pair --rom '/absolute/path/天地创造.sfc' \
  --profile 2 --frames 600 --out /tmp/quintet-private-results \
  --state '/absolute/path/private-native.state' \
  --script '/absolute/path/private-controller.keys' --present-every 4
```

输入脚本每行 `开始帧 结束帧 按键十六进制掩码`，区间左闭右开，掩码使用 libretro 标准 SNES 位序。省略 `--state` 可从标题启动，省略 `--script` 则不输入。`--profile 1` 对应创世封魔录。对照完整 CPU/内存/音频状态，并逐行比较未有意改动的原始画面区域；地图审计独立比较 WRAM 完整地图与原版 VRAM。

## 0.1.2 显示修正

三款游戏现在共用 `shared/portrait_rules.h` 的窗口、10 位滚动、OBJ 图块回绕和 OAM 遮挡规则（盖亚仓库保留相同文件）。`tools/test_portrait_rules.c` 在 CI 检查边界与遮挡。具体的 WRAM 地图、动态美术、角色列表仍按游戏适配；此版本继续使用 Snes9x 执行原版游戏。

- 在可见帧开始锁定显示所需的角色数据，避免把下一帧动作接到当前原始画面上；修正 OBJ 垂直位置与相同深度排序。
- 颜色运算遵循本核心的 RGB565 输出与逐行亮度，消除创世封魔录云层的绿色精度接缝。
- 当前帧重置光栅缓存；加载中的地图需通过 VRAM 对照。不支持的马赛克/大图块布局回到原始视野。
- 原始画面中需要重绘的区域每帧只计算一次，降低重复判断开销。
- Debug 构建使用独立 `.qa` 包，测试进度与正式版隔离；正式版保持既有包名和存档。

开发诊断可设置 `QUINTET_RECONSTRUCT_NATIVE=1`，让扩图路径重绘原始视野，用独立的原版渲染检查地图、精灵和混色。这个模式会省略 BG3 对话与 HUD，仅用于本地开发，不能作为正常游玩模式。普通构建继续保留完整原始画面。完整对照状态应始终一致，但重绘目前只在有限场景验证，未承诺所有动作、特效和地图逐像素相同。

## 0.1.3 音频启动与恢复

冷启动必须先按硬件原速完成 SPC 程序上传，确认 DSP 退出复位/静音、完成初始化并有有效声部后，才启用正常音乐速率的倍速运行。先从已播放音乐的状态测试无法覆盖这个上传时序错误；新增 `tools/verify_audio_startup.py` 从冷启动验证 1/2/4 倍速。测试输出包含私有游戏数据，不能提交。

Android 17 宿主在获得前台窗口和音频焦点后创建 AudioTrack；离开前台或丢失焦点时标记旧轨道失效，恢复后重建，避免后台音频限制使旧轨道持续静音。写入失败时同样重建。

已经保存到旧续玩文件的损坏 SPC 状态不会仅凭音频焦点恢复；本轮在单独备份后对本地两个续玩文件只修复声音块，完整保留其他游戏状态。修复用的声音数据及用户存档不发布到仓库。


## 0.1.4 行走节奏与声音通信

旧版阻塞式 AudioTrack 写入会让画面先等待音频设备，再连续补帧。现在用屏幕垂直同步发放显示帧，丢弃过期显示许可；PCM 通过有界队列非阻塞写入，保留未完全接受的样本，恢复前台时清除旧队列。显示刷新与 SNES 频率的微小差异由输出采样率补偿，避免周期性积压。`tools/verify_pcm_queue.py` 验证短写、背压、环形回绕和失败恢复。

倍速仍保持音乐原速，但不再降低 SPC 指令执行/CPU 通信的时钟；仅音乐定时器和 DSP 按音乐速率运行，避免场景、音效指令或后续上传受慢速握手影响。冷启动仍先完成正常硬件时序初始化。1× 路径的完整游戏状态和 PCM 已与修复前逐字节对照一致。

方向键与摇杆/HAT 独立保存再合并，避免中立轴事件取消仍按住的方向键。已有速度设置保持，新安装默认 1×。

损坏的旧声音状态需要另行备份和针对场景修复；不能仅因新版本有输出就宣称旧进度中的音乐已恢复。此版本未内置任意地图的存档声音替换。


## 0.1.5 普通手柄与 FlipPad 布局分离

只有非虚拟、具有游戏手柄/摇杆输入源、硬件 ID 为 `2dc8:3022` 的 FlipPad 才启用弧形底边和专用竖屏布局。消费按键接口或普通手柄不能触发这个布局。

Backbone 等普通手柄使用完整屏幕，不显示虚拟按键；接入时进入横屏，左右横屏方向跟随传感器。拔掉所有手柄后恢复竖屏和底部虚拟按键。界面和原始 256×224 游戏区域在横屏时仍完整可见，地图在四周继续扩展。

`tools/verify_controller_layout.py` 检查实际 Backbone ID `358a:0304`、FlipPad、消费接口和无手柄状态，以及 Pixel 9 横屏的缩放边界。实体 Backbone 主屏测试与模拟 FlipPad 插拔测试分别记录，模拟插拔不能代替实体 FlipPad 手感验收。


## 0.1.6 xBRZ 性能

保留 2× / 3× xBRZ 的原像素结果：不透明 RGB565 帧先缓存调色板的精确 RGB 距离，再由最多四个常驻执行线程处理互不重叠的图像分段。只更新变化区域及两行分析边界；静止帧不重复缩放或写入目标 Bitmap。超出调色板容量的场景使用通用 RGB 路径，仍保留原颜色和阈值。Android 上尊重线程允许使用的 CPU，优先把滤镜工作安排到性能核心，完成后恢复调用线程的原 CPU 范围。

`tools/filter_check.cpp` 将输出逐像素与原 ARGB xBRZ 对照，覆盖图像边界、分段、动态更新、调色板与通用路径、缩放/视口变化及缓存失效。线程检查也通过。CI 无需私有游戏即可运行这些检查。

Pixel 9 实机独立测试副本，xBRZ 3×、同一初始进度及相同行走输入：竖屏两款约 60 FPS；606×272 宽横屏创世约 42→58 FPS，天地约 40→53 FPS。宽横屏复杂场景仍可能低于 60 FPS，不能视为全流程满帧验收。游戏执行、音乐时序、地图数据及存档格式未修改；盖亚未修改。


## 0.1.7 横屏并行显示

游戏与 PCM 仍由同一个执行线程顺序生成，滤镜与画面提交移到独立显示线程。三个有界源缓冲按 FIFO 交接所有权：正常游玩不覆盖未显示帧、不靠跳帧提高统计数字；全满时执行线程等待空缓冲。改变布局、打开助手或进入后台时丢弃旧显示配置的在途画面，退出时唤醒所有等待者，最后一个持有者才回收源 Bitmap。

xBRZ 先准备完成，再短时锁定 Surface；根据原 Choreographer 时间对齐提交，减少异步执行造成的显示间隔波动。滤镜最多三个执行线程，减少与游戏执行线程对性能核心的争用。保留相同 xBRZ 算法、精确颜色距离、3× 输出、完整视野和变化区域复用；未替换成近似滤镜，也未调整游戏或音频速度。对齐提交会增加少量画面缓冲等待。

`tools/FrameExchangeCheck.java` 验证 12,000 帧 FIFO 顺序、像素所有权、有界背压及关闭唤醒，CI 同时运行原有逐像素滤镜检查。实机统计区分 `TallPerf` 的游戏执行速率与 `TallRender` 的实际画面提交速率，并通过 SurfaceFlinger 采样核对显示间隔。60 FPS 均值不能代表每一帧都恰好 16.67 ms，也不能代替整部游戏或物理手柄手感验收。

功耗应在相同场景和输入下读取 Pixel 的 ODPM 电源轨进行比较。减少线程和稳定 60 FPS 并不自动等于省电；电源轨包含其他进程和系统开销，短时间测试不能换算为电池续航。此版仍使用 CPU xBRZ，尚未加入 GPU 滤镜。


Pixel 9 0.1.7 独立测试副本，606×272 横屏源画面、xBRZ 3×、相同初始进度与四方向循环行走：两款约 90 秒测试的画面提交均值均为 59.99 FPS，三秒窗口约 59.75～60.21 FPS，未记录滤镜回退、显示错误或 AudioTrack 欠载。SurfaceFlinger 分段采样仍有约 25 ms 间隔，天地创造样本最大约 33.42 ms；这不代表全程每帧精确 16.67 ms。输入设备是模拟 USB 游戏手柄，未将其计作实体 Backbone/FlipPad 的手感验收。


## 0.1.8 天地创造举物与对话显示

天地创造的地图、元图块定义、相机与显示状态改为读取可见帧开始时已存在的 WRAM 快照，与当前原生 VRAM/光栅同步。举起物品时，游戏先修改下一次 VBlank 要上传的地图；旧路径在当前画面中读取到下一帧地图，导致 `map_ready` 失败一帧，整个扩展区域回退黑色。此修改保留地图一致性检查，不放宽加载场景的准入条件，也不重复上一帧画面。

对话占有文字窗口时仍清除旧 256×224 视野的边框，仅替换外圈精确的 BG3 `$2820` 实心图块。对话框边线和文字保留原像素，物品菜单仍保留独立布局资格检查；HUD 由实际图块内容判定，不再因文字忙标志跳回旧位置。仅天地创造的地图读取使用该帧快照，创世封魔录的读取规则沿用原实现。

私有 ROM 的举起/投掷与农民对话场景各逐帧对照 240 帧，共 480 张原生/扩图画面对照，完整状态、原生画面内部及 860,160 项地图字一致。修复前后相同输入的完整状态、WRAM、VRAM 和 PCM 字节也一致。测试场景由独立副本建立，不写入用户正式进度；不代表所有地图、剧情或互动已完成通关验证。

`tools/verify_quintet.py --snapshot-every 1` 可保留每一显示帧用于瞬时错误回归；默认仍为 300 帧间隔。测试进度与 ROM 必须由本地提供，输出不能提交到仓库。


Pixel 9 主屏在实体 Backbone 已连接的状态下，用独立 QA 副本与定时按键重现：0.1.7 录屏捕获举物时 1 帧扩图全黑，对话时旧边框持续出现；0.1.8 六段对应录屏（扫描线 1×/2×、xBRZ 3× 的举物/投掷和对话）逐帧检查均未再检测到这两类错误。录屏检测基于该场景的固定区域，不能证明所有地图无错；输入由 ADB 注入，不计作实体按键手感验收。
